# SDD-010｜30 分鐘核心課真實學習時間校準

- 工程項目：ENG-010
- 狀態：規格、匿名採樣表與計時覆蓋盤點已完成；真實學習者試用及時間數據未取得
- 上游：SDD-006（30 分鐘核心課）、ENG-008（U01–U04 上線）

## 背景與需求

App 目前為每堂課配置六階段、合計 30 分鐘，但這是設計預算，不是實測承諾。現有程式 `js/store.js` 的 stopwatch 只覆蓋特定聽力、複習、對話與影片頁；課前詞彙、課程路線、理解測驗及靜默口說任務沒有完整課程計時。既有 sessions 只有 mode、lessonId、秒數與時間戳，不能重建單一學習者完成六階段的完整時間，也未能辨認完整課程嘗試。

| ID | 需求 | 驗收條件 |
|---|---|---|
| TC-01 | 先定義時間量測 | 區分六階段有效學習分鐘、離開／休息時間及整體牆鐘時間；定義跳過、重聽、查詞與中斷的記錄方式 |
| TC-02 | 按程度取得真實資料 | L1–L5 均有實際完成的課程樣本，並記錄課程型態／句數；不以 L1 單課或開發者推估代表全部級別 |
| TC-03 | 保護學習者隱私 | 僅用匿名代碼、級別、課程 ID 和必要時間／行為計數；不收集姓名、聲音、逐字回答、API key、病歷或聯絡資料；資料預設由使用者保存在本機 |
| TC-04 | 以穩健統計比較目標 | 各級別至少 5 個有效完成樣本後才作初步調整建議；回報中位數、P75、樣本數與缺漏，不宣稱小樣本有統計代表性 |
| TC-05 | 對應教學決策 | 依分階段耗時、跳過率、重聽／查詞需求及理解任務完成情形決定增減時間或核心量；不得只追求總分鐘數 |
| TC-06 | 程式變更需另案核准 | 本輪只建立協定／空白表，不新增追蹤、遙測、帳號或後端；若要完整自動計時，先另立 SDD 評估裝置本機資料和同意流程 |
| TC-07 | 工程追溯 | 規格、空白記錄表、施工紀錄、know-how 與索引互連；沒有實際試用資料時明確標示未校準 |

## 非目標

- 不從未關聯的既有 session 記錄反推一堂課總完成時間。
- 不在使用者不知情下讀取／上傳 IndexedDB 學習紀錄，不新增雲端分析或遙測。
- 不用自動化測試、模型模擬、開發者估時取代真實學習者。
- 不在樣本數不足或只測單一等級時，改動六階段時間／核心句數上限。

## 量測定義與流程

1. 參與者依自身熟悉度由教師／使用者指定級別與代表課，不向參與者顯示對話全文或正解作首聽預熱。
2. 記錄每一階段的有效分鐘。離開頁面、接電話、用餐等暫停不計入有效分鐘，另外標示是否發生；正常查詞、重聽與開口時間計入。
3. 記錄完成／中斷、跳過階段、提示等級、重聽回合數與理解題結果；不錄音、不抄參與者的口說逐字稿。
4. 每個 L1–L5 級別先收至少 5 個有效完成樣本；同級需涵蓋短情境與長內容等實際可用型態。先報描述統計，中位數／P75，不把它稱作正式效果研究。
5. 若全程有效時間明顯偏離 30 分鐘，先檢查階段和跳過情況；只有能解釋偏差的樣本才支持調整。任何改動另開程式 SDD、測試與使用者同意流程。

## 資料流程與相容性

```text
現行時間預算（六階段合計 30 分鐘）
        ↓ 待驗證，不視為真實完成時間
真實學習者逐階段試用 → 匿名記錄表（本機） → L1–L5 中位數／P75 與行為對照
        ↓
教師／使用者內容判讀 → 若有證據，再另立程式變更 SDD
```

本工程不讀取或更動 `sessions` / `lessons` / `cards` 等 IndexedDB store，不改其 schema、備份、SRS 或既有時間計數 UI。現有 sessions 可作活動累積參考，不能被重新命名為「完整課程時間」。
