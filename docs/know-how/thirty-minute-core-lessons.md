# Know-how｜用核心訓練控制課程時間，不犧牲完整內容

## 1. 字數不是上課時間

500 字故事很適合提供語境與泛聽素材，但不適合把每一句都做盲聽、放慢、揭示、跟讀、錄音與 SRS 評分。時間預算應綁定「本輪深度處理幾句」，不是只綁全文字數。

可重用做法是保存兩個層次：

- 完整內容：閱讀、首聽、查詞與延伸。
- 核心集合：在預定時間內完成的精聽、理解與開口。

短內容不需要刻意節錄；若全文已可在時間內完成，核心集合就等於全文。

## 2. 自動選句必須穩定而可人工覆寫

隨機選句會讓相同網址每次出現不同內容，也會讓進度與測試難以解釋。核心選句應使用穩定優先序：

1. 首句與末句，保留進入與收束。
2. 結構段落起點，保留故事骨架。
3. 理解題引用句，讓訓練支持檢核。
4. 依全文位置均勻補足，避免只集中前半段。

自動規則只能當可靠預設。編輯成熟後仍應允許人工提供原句 ID；驗證器必須檢查 ID 存在、沒有重複且數量合理。

## 3. 篩選練習集合，不複製課程

核心模式不應建立第二份句子或第二套進度：

- 畫面使用過濾後的 sentence array。
- 播放、SRS、查詞與任務仍使用原 lesson ID、sentence ID。
- 理解題仍使用完整課程資料。

這能避免同一句因「核心版」與「完整版」產生兩張 SRS 卡，也保住舊網址與備份格式。

## 4. 相容路由要保留原意

新增 `.../core` 比把舊的完整精聽網址偷偷改成節錄更安全。舊書籤仍代表全文，新入口明確代表核心課，完成頁也要說清楚「完成核心」不等於「逐句完成全文」。

若 router 有 optional capture，解碼時要保留 `undefined`，避免把缺少的參數變成字串 `"undefined"`。

## 5. 預設值不等於遷移既有偏好

把新使用者的每日目標設為 30 分鐘，只需調整 default。已有設定應由儲存值覆蓋 default，不可因課程重新設計就把使用者明確選過的 15、20 或 45 分鐘改掉。

## 6. PWA UI 驗收要防舊 cache 假象

尚未發布的新 shell 在既有 localhost origin 可能仍由舊 service worker 提供。驗收時可使用另一個純本機 port 建立乾淨 origin，確認新檔案；測試結束關閉暫時分頁與伺服器。

自動導航後音訊出現 `not-allowed` 通常是瀏覽器要求真實使用者手勢，不等於檔案或路由失效。紀錄時要把「畫面／路由通過」與「真人點擊後播放」分開，不可把未執行的音訊驗收寫成通過。

## 7. 仍需真人時間校準

六階段加總 30 分鐘只是產品承諾與教學預算。不同程度、句長、錄音次數與查詞行為會改變實際時間。正式擴大課程前應記錄：

- 完成核心句的中位時間與 P75。
- 哪個階段最常超時或被跳過。
- L1–L5 是否需要不同核心句上限。
- 10 句是否讓初學者太重、進階者太輕。

只有取得實際完成時間後，才適合調整各等級門檻，不應用單一 500 字規則代替。
