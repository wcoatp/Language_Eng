## 施工節點

### N0｜範圍、既有變更與來源

- 先讀 [工程索引](../engineering/README.md)；工作樹原有未追蹤的使用者 PDF，明確排除於本次提交與 Hosting 範圍。
- 按 PDF 技能唯讀檢視來源，核對 U05–U08 原頁 58–72：U05 冷氣維修；U06 入境與旅館入住等場景；U07 緊急就醫登記／診療；U08 租車車況與道路支援。
- 舊藍圖的 U05／U08 第一輪描述較籠統；本稿以來源主題重新設定候選學習任務。只借用情境功能，不照搬角色、品牌、地址、劇情或原句。
- 比對既有課庫：`l3-02` 租屋維修、`l1-04` 入住、`l2-07` 等房、`l2-04` 看診與 `l1-07` 餐點更換。

### N1｜先立規格與重複度閘門

- 建立 SDD-009，明定 U05–U08 的來源核對、原創內容、難度候選、重複檢查、安全界線與非目標。
- 判定 U05、U06、U07、U08 各自候選為新的 L2 溝通技能：報修約訪、確認附加費、診所登記、道路支援聯絡。皆有相鄰既有課，但沒有完全相同的目標；正式課程 ID 留到實作 SDD 才決定。
- 建立 SDD-010 作為另一獨立工作：既有 30 分鐘目標需要實測，不將本次內容時間估算冒充真實學習者數據。

### N2｜原創課程稿

- 每課編寫 6 個英中／簡明英英詞條、10 回合雙語對話、3 題附回合證據的首聽題、條件替換任務、逐層提示、挑戰題及口語補充。
- U05 僅描述冷氣暖風並約時段；不診斷、估價。U06 只練附加費與確認，不沿用旅館升等或私人入境資料。U07 不確定過敏時如實記錄，不提供診療建議。U08 以前提「已停於安全位置」聯絡支援，不鼓勵冒險駕駛或保證賠償。
- 將首版藍圖中的 U08 訂單退換草稿改為租車道路支援的審稿結論；舊藍圖保留作第一輪設計紀錄，以本稿為 U05–U08 編輯版。

### N3｜30 分鐘資料現況與採樣工具

- 程式碼盤點 `js/store.js`、`js/db.js` 與計時頁面：目前 stopwatch 覆蓋特定聽力／複習／對話／影片活動；預習詞、課程路線、理解題及靜默口說任務未完整計時，既有 session 欄位也無法還原六階段課程嘗試。
- 沒有讀取／匯出個人 IndexedDB 資料，也沒有把個人記錄或全文傳出裝置；程式碼盤點不等於取得實際學習者時間。
- 建立 [匿名空白試用表](../research/30-minute-course-pilot-template.md)：記錄六階段、休息、提示、重聽、查詞、完成狀態及理解題數，不記個資／錄音。
- 研究門檻定為每級 L1–L5 各至少 5 筆有效完成，再計算中位數、P75；目前沒有任何真實樣本，因此時間校準仍未完成。

### N4｜QA 與驗收

- 手工檢查四篇章的欄位結構、對話 10 回合、詞彙數 6、理解題 3 題與答案依據回合存在；檢查稿件安全限制與學習目標一致。
- 本輪文件範圍未改程式／內容 JSON／路由／版號，因此沒有執行會變更或部署 App 的操作；後續若轉成 lesson JSON，需另立實作 SDD 並跑 `npm run check` 及 UI 驗收。
- 沒有教師／目標學生審稿、真人教學試驗或時間數據；不能把可讀性人工檢查說成教學成效驗證。

- 請使用者／英文教師先審核 U05–U08 雙語台詞、L2 難度與目標是否值得新增四課。通過後才立 lesson JSON 實作 SDD。
